# Polar Pyro Industrial Plugin Execution Roadmap

## Dependency order

The safe order is Sandbox → Shell → Git local transactions → proof gateway → Prose retrieval/memory integration → Cybersecurity → DE-PIN protocol extraction. Prose's pure claim compiler can progress in parallel, but any generated code, external tool, browser, or corpus-processing job must ultimately run on the sandbox substrate. Git promotion depends on completed oracle receipts, so it follows the execution boundary rather than preceding it.

## Continuous long-horizon loop

Each phase executes the same transaction:

1. load the frozen task, registry, policy, model, source, and prior-certificate hashes;
2. restore only a checkpoint whose hashes match;
3. compile a bounded cheat sheet and current residual;
4. allow Qwen3-0.6B to emit one grammar-constrained intent/spec/patch;
5. validate symbols and effects before capability selection;
6. execute in a disposable attempt scope;
7. collect nonempty evidence from deterministic/domain oracles;
8. map `FAIL` to typed residual and retry within budget;
9. preserve `NO_RESULT` as abstention;
10. promote atomically through the Git proof gateway only on complete `PASS`;
11. journal canonical records and certificates in TOAM;
12. run regression, mutation, security, performance, and UI conformance suites;
13. publish pinned artifacts and update the software directory.

No phase is declared production-ready because its happy path works. Production readiness requires restart/recovery, rollback, tenant isolation, supply-chain provenance, threat-model closure, resource budgets, observability, and an independently reproduced qualification report.

## Integrated milestones

### M1 — Trusted execution substrate
Deliver Sandbox X0–X4 and Shell S0–S4. Gate: generated work cannot affect canonical files, network, secrets, or child processes outside declared effects.

### M2 — Proof-carrying workspace
Deliver Git G0–G3 and bind it to `WorkspaceTransaction`, TOAM, DEMIURGE, LOOM, and SAE. Gate: no unverified mutation reaches a protected branch.

### M3 — Evidence-bound communication
Deliver Prose P0–P6 with sovereign retrieval and memory adapters. Gate: facts are cited, raw research is purged, repairs are bounded, and final prose cannot alter the certified plan.

### M4 — Measured synthesis improvement
Run Prose P7 against DEMIURGE/LOOM/SAE. Gate: frozen experiments show improved oracle pass rate or reduced repair/time; prose is removed from the machine path if it only sounds better.

### M5 — Defensive security
Deliver Cyber C0–C4 atop Sandbox/Shell/Git. Gate: authorized, evidence-backed repair workflows pass seeded vulnerability and containment suites.

### M6 — Modular DE-PIN platform
Deliver D0–D5, beginning with prior-art inventory. Gate: each extracted protocol has one canonical repo, independent UI, pinned host contract, and rollback isolation.

### M7 — Autonomy and human gates
Run the autonomy gauntlet across difficult stateless and stateful applications without product hand edits. Machine gates cover correctness/security/performance; browser and human review cover aesthetic and experiential residue. Ten successful projects are evidence only when their provenance proves the harness—not a human—created each candidate, and every later natural-language change follows the same transactional path.

## Honest claim standard

The ambition to rival frontier coding systems is a benchmark target. It becomes a defensible claim only per measured domain and hardware configuration. Parameter-count rhetoric is never used as a release gate; reproducible task success, correctness, safety, time, cost, and human judgment are.
